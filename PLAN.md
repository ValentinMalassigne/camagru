# Camagru — Plan

Ordered plan for the whole project. The agent follows this order and ticks the boxes as work advances.

**Current step:** Phase 1

## Rules for ticking

- Follow the order below. Do not skip or reorder steps without asking the user.
- Tick a task box (`- [x]`) only after you ran and verified it. Never tick in advance. Items marked **(you)** are ticked only after the user confirms.
- Each step ends with a **Checkpoint** box. Tick it only when all of these are true:
  1. You ran the step: `docker compose up --build` works, `docker compose logs` is clean (console output policy in `AGENTS.md`), the browser console is clean, and the matching items of spec section 13 pass.
  2. You gave the user the Firefox 41 / Chrome 46 smoke-test list for the step (pages load, narrow layout, clean console, the step's flow).
  3. The user reported their VM results (or explicitly skipped them for this step). Problems are logged in `COMPATIBILITY.md`.
  4. The user gave the go-ahead.
- After a checkpoint, update the **Current step** line above.
- If a task is blocked or a decision is needed, leave the box unticked and write it in the Notes section at the end. Ask the user when an instruction is a problem.

## Phase 2 — Accounts

### 2.1 Mailer, registration, email confirmation
- [ ] `Mailer` interface, `MessageBuilder` (CR/LF stripping, RFC 2047 subject), `MsmtpMailer`, `MailerFactory`, `AppMailer::sendVerification()`
- [ ] msmtp config generated by `entrypoint.sh` (log to a file, never the console)
- [ ] `users` table added to `db/schema.sql`
- [ ] Register form with server-side validation (email, username 3–20 `[A-Za-z0-9_]`, password 8+ with lowercase, uppercase, digit); username and email unique, case-insensitive
- [ ] Password stored with `password_hash`; confirmation token random and stored hashed
- [ ] Confirmation email sent; `/verify?token=` activates the account; login refused until verified
- [ ] Mail failures logged to a file and never break the request
